# Transactional Email Operations Runbook (`REQ-077`, `DEC-031`, `DEC-038`, `DEC-041`)

This runbook documents domain onboarding, DNS authentication, sender restrictions, suppression handling, fallback switchover, and staging verification for PunyaSitus transactional email.

## 1. Architecture Overview

- **Single Port (`EmailPort`):** All transactional mail flows through `packages/core/src/email/` and durable Queue jobs (`email.transactional.send` on `JOBS_QUEUE`).
- **Primary Provider:** Cloudflare Email Service (`env.EMAIL.send()` Workers binding on Workers Paid, no API key required).
- **Optional Fallback:** Resend HTTP API (`https://api.resend.com/emails`) enabled only via runtime configuration when Cloudflare Email Service is unavailable.
- **Local & CI Runs:** Use `createLocalMailSink()` in memory; never send live mail from local dev or automated tests.
- **Allowed Sender:** Strictly restricted to `noreply@notif.punyasitus.com`. Any attempt to send from another address fails closed with `E_SENDER_NOT_VERIFIED`.
- **Attachments:** PDF payment receipts are always Base64-encoded strings (`contentType: "application/pdf"` / Cloudflare `type: "application/pdf"`, `disposition: "attachment"`).
- **One-Shot Safety (`PLAN §17.4`):** Because `env.EMAIL.send()` has no provider idempotency key, each send atomically claims `message_key` in `PLATFORM_DB.email_delivery_claims` before calling `send()`. An ambiguous timeout/network error is recorded as `unknown` and is **never replayed**. Only definite pre-accept refusals (e.g. `E_RATE_LIMITED`) retry with bounded exponential backoff. `email_delivery_claims` stores zero recipient email addresses and zero email body text.

## 2. Cloudflare Email Service Domain Onboarding (`notif.punyasitus.com`)

### Prerequisites
- Account is on **Workers Paid** plan (required to send to arbitrary customer addresses).
- `punyasitus.com` DNS zone is authoritative on Cloudflare DNS.

### Onboarding Commands
Run only with explicit operator approval against the target Cloudflare account:

```bash
# 1. Inspect currently onboarded sending domains
npx wrangler email sending list

# 2. Enable Email Sending on the dedicated transactional subdomain
npx wrangler email sending enable notif.punyasitus.com

# 3. Verify domain status and generated DNS records
npx wrangler email sending status notif.punyasitus.com
```

### Worker Binding Configuration (`apps/web/wrangler.jsonc`)
Verify the binding stays locked to the single transactional sender address:

```jsonc
"send_email": [
  {
    "name": "EMAIL",
    "allowed_sender_addresses": ["noreply@notif.punyasitus.com"]
  }
]
```

> Do **not** restrict destination addresses in production (customers register with arbitrary email providers). Before domain onboarding completes, Cloudflare restricts sends to verified destination addresses in the account — use that behavior for staging validation.

## 3. SPF, DKIM, and DMARC DNS Records (`notif.punyasitus.com`)

Publish and verify all three authentication records on the `notif.punyasitus.com` subdomain (isolated from root `punyasitus.com` corporate mail reputation):

| Type | Name | Value / Target | Purpose |
|------|------|----------------|---------|
| `TXT` | `notif.punyasitus.com` | `v=spf1 include:_spf.mx.cloudflare.net ~all` (or exact SPF value issued by Cloudflare Email Sending onboarding; add `include:amazonses.com` / Resend SPF only if Resend fallback is actively enabled) | Authorizes Cloudflare Email Service sending IPs |
| `CNAME` / `TXT` | `<selector>._domainkey.notif.punyasitus.com` | Exact DKIM selector records generated by `wrangler email sending enable notif.punyasitus.com` | Cryptographic DKIM signing for `notif.punyasitus.com` |
| `TXT` | `_dmarc.notif.punyasitus.com` | `v=DMARC1; p=quarantine; sp=quarantine; adkim=s; aspf=s; rua=mailto:dmarc@punyasitus.com; pct=100` (graduate to `p=reject` after 14 days of clean DMARC aggregate reports) | Enforces strict DKIM/SPF alignment and reporting |
| `MX` | `notif.punyasitus.com` | Cloudflare bounce/return-path MX issued during onboarding | Receives SMTP bounces for automated suppression |

### DNS Verification Checks
```bash
dig +short TXT notif.punyasitus.com
dig +short TXT _dmarc.notif.punyasitus.com
dig +short TXT <selector>._domainkey.notif.punyasitus.com
```

## 4. Suppression Handling & Bounce Webhooks

- **Storage:** `PLATFORM_DB.email_suppressions` stores only the lowercase SHA-256 hash (`email_hash`) of the normalized email address (with optional `EMAIL_SUPPRESSION_SALT`), `reason` (`hard_bounce`, `complaint`, `manual_opt_out`), `source`, and `created_at`.
- **Provider Suppression:** When `env.EMAIL.send()` returns `E_RECIPIENT_SUPPRESSED`, the queue handler records the hash in `email_suppressions`, marks `email_delivery_claims.status = 'skipped'` (no retry), and emits a visible Bahasa Indonesia warning banner via `getSuppressionNoticeForOwner()`.
- **Access Invariant:** Email suppression or send failure **never** blocks login, dashboard access, or public site serving.
- **Optional Signed Bounce/Complaint Webhook (`POST /api/webhooks/email/bounce`):**
  - Requires `EMAIL_WEBHOOK_SECRET` configured via Cloudflare Worker secret (`wrangler secret put EMAIL_WEBHOOK_SECRET`).
  - Verifies `X-Webhook-Signature` (`sha256=<HMAC-SHA256(secret, "${timestamp}.${rawBody}")>`) and `X-Webhook-Timestamp` within a 5-minute replay window, plus atomic `event_id` deduplication in `PLATFORM_DB.email_webhook_events`.
  - Unsigned or invalid-signature requests fail closed with `401`; replayed event IDs fail with `409`.
  - Hard bounces (`hard_bounce` / `email.bounced`) and complaints (`complaint` / `email.complained`) add the recipient hash to `email_suppressions`.

## 5. Resend Fallback Switchover Procedure

Use only if Cloudflare Email Service experiences a prolonged outage affecting transactional authentication or billing receipts:

1. Verify `notif.punyasitus.com` DKIM/SPF domain verification is pre-configured in Resend (matching `noreply@notif.punyasitus.com`).
2. Set Worker secret `RESEND_API_KEY` and configure `EMAIL_PROVIDER=resend` (and `EMAIL_WEBHOOK_SECRET` for Resend bounce webhook sync to `/api/webhooks/email/bounce`).
3. Confirm one synthetic staging email succeeds with `provider: "resend"` in `email_delivery_claims`.
4. After Cloudflare Email Service recovers, remove `EMAIL_PROVIDER=resend` (defaults back to `cloudflare` primary) and verify `provider: "cloudflare"`.
